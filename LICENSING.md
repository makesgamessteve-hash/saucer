# Licensing

Saucer uses three licenses. Each file's license is machine-readable via
[REUSE.toml](REUSE.toml) and, for assets, via its `.meta.lua` sidecar.

| What | License | Text |
|---|---|---|
| Code: engine C, Lua game scripts, mesh recipes (`data/base/meshes/*.lua`), tools, tests, build files, web shell | MIT | [LICENSES/MIT.txt](LICENSES/MIT.txt) |
| Hand-made or code-generated art and sound: `data/base/authored/**` (palettes, sprites, sounds) | CC BY 4.0 | [LICENSES/CC-BY-4.0.txt](LICENSES/CC-BY-4.0.txt) |
| Images generated with Grok Imagine: `data/base/generated/**`, `art/src/generated/**` | LicenseRef-xAI-Output (xAI terms, "Created with Grok") | [LICENSES/LicenseRef-xAI-Output.md](LICENSES/LicenseRef-xAI-Output.md) |
| Vendored Lua 5.4 | MIT (Lua.org, PUC-Rio) | [third_party/lua/LICENSE](third_party/lua/LICENSE) |
| Vendored stb_image / stb_image_write | Public domain / MIT (dual) | header of each file in [third_party/stb](third_party/stb) |

Hero meshes (saucers, station, loot caches, derelict greebles) are not
binary assets: they are built at load time by the MIT-licensed Lua recipes in
`data/base/meshes/`, so they fall under MIT as code.

## Credits

[ATTRIBUTION.md](ATTRIBUTION.md) lists every asset with its license and
credit. It is generated by `python3 tools/artpipe/artpipe.py build`, and
`python3 tools/artpipe/artpipe.py lint` (run in CI) fails when an asset lacks a
sidecar, a sidecar names an unknown license, or a generated image has no
prompt in `art/prompts/log.jsonl`.

CC BY 4.0 credit line: "Saucer art by Steve Makesgames and contributors,
CC BY 4.0".

## Mods

Mods declare `license_code` and `license_assets` in their `mod.lua`. Mods
are separate works; the base game's licenses do not cover them.
